Vision

A roguelike dungeon crawler built for couch co-op. Every run starts clean — no meta-progression, no permanent unlocks. Players pick from a roster of four distinct classes, each with a fixed weapon and different stat profile, then descend through 10 floors of dungeon rooms. Challenges vary — combat arenas, mazes, puzzles, boss encounters. Items found along the way define the run. A single dungeon environment throughout; beat floor 10 to win. Pixel art, top-down, Zelda-paced.

Room Types

Room types are assigned by a per-room weighted roll after the dungeon graph is generated. Boss is the only fixed count (exactly 1 per floor, random placement). All others are probabilistic — average counts assume ~13 rooms per floor.

Combat Phase 1 · 58%
The default (~7 per floor). Clear all enemies to unlock the exit doors. Semi-open layout with random tetris-block cover obstacles — some rooms are fully open, most have light cover. Cover is randomly generated per room.
Boss Phase 4 · fixed 1
Exactly 1 per floor, randomly placed in any room except the spawn room — independent of the stairs. Floors 1–9: mini-boss (same structure, weaker stats). Floor 10: final boss. Open arena layout. Telegraph: passageway tiles leading into this room are colored gold.
Maze Phase 4 · 17%
~2 per floor. Recursive backtracking wall layout, enemies scattered throughout. Navigation is the challenge — no special clear condition beyond reaching the exit.
Chest Phase 4
No combat. Guaranteed item drop on entry — upgrade or equipment. Spawn chance TBD.
Puzzle Phase 4 · tabled
Tabled for a later phase — needs proper design space. Interactive objects trigger environmental changes (e.g. lever removes fire blocking a door). Currently filled by Maze rooms in the floor composition.
Trap Tile Phase 4 · ~1%/room
Not a dedicated room type — a tile that can spawn inside any eligible room (excludes shop, shrine, boss). ~1% chance per eligible room, giving ~10% cumulative odds per floor. Warps all players forward N floors. Players can see it and opt not to step on it.
Shop Phase 5 · 17%
~2 per floor. Spend HP to buy from a shared item pool — one pool for the whole team, so players decide together who gets what. No gold system needed.
Healing Shrine Phase 5 · 8%
~1 per floor. No enemies. Restore partial HP on entry — a deliberate breath room. Each player heals independently on entry.
Wave Phase 5
Enemies spawn in sequential waves. Doors don't open until all waves are cleared. Upgrade drops after the final wave. Spawn chance TBD.
Bounty Phase 5
One named champion enemy with a guaranteed rare item. Spawn chance TBD.
Darkness Phase 5
Severely limited visibility radius around each player. Enemies harder to spot; combat becomes more tense and unpredictable.

FLOOR 1 Rooms & Floors Done ▶
Milestone: Enter a room, clear it, walk through a door, and descend a floor.
  • ✓ Dungeon generator: 5×4 grid of 21×16-tile rooms, random walk with 60% neighbor chance, seeded RNG, barriers between rooms
  • ✓ Room type assignment: weighted roll per room (58% Combat / 17% Maze / 17% Shop / 8% Shrine / 1 fixed Boss)
  • ✓ Combat room carve function: semi-open layout with randomly placed tetris-block cover (25% chance fully open)
  • ✓ Boss room placement: random non-spawn room; gold breathing passageway tiles as in-world telegraph
  • ✓ Enemy spawning per room: type-aware (skips boss/shop/shrine), count scaled by floor & player count
  • ✓ Door lock/unlock: lock on entry if enemies present; unlock on clear; empty rooms never lock
  • ✓ Stairs: stepping on stairs tile descends to next floor; difficulty scales
  • ✓ Room transition: camera pan on room entry (current behavior accepted)
Art needed: None for MVP — doors, stairs, and cover blocks can be colored tiles. Gold passageway tiles for boss are a tile color change.
FLOOR 2 Characters & Projectiles Done ▶
Milestone: All four classes are playable with distinct-feeling weapons.
  • ✓ Character picker before floor 1 loads; per-class stats wired in (class × skin as separate axes). (The join-time weapon picker was later removed — players now spawn empty-handed and claim their first weapon at the floor-1 supply room; the weapon picker survives only in the Debug menu.)
  • ✓ ProjectileState schema + GameState.projectiles MapSchema; server ticks all active projectiles (kinematic, no matter-js body)
  • ✓ Rogue: fast thrown dagger/star, 1 hit, despawns on wall hit
  • ✓ Ranger: traveling arrow, 1 hit, despawns on wall hit
  • ✓ Mage: staves fire a per-staff elemental bolt (rangedStyle: "cast"); the AOE nova is built and reserved as a Mage ability
  • ✓ Client renders projectile entities from AMMO_REGISTRY
Landed early beyond scope: the full Super Overhead Adventure 2 pack (12 humanoid skins, 29 enemies, 8 bosses); a unified combat resolver + single Spell type (windUp→strike→active→recover) shared by players, enemies, and bosses; five elemental bolts with cast + nova client FX.
FLOOR 3 Upgrade System Done ▶
Milestone: Picking up an item changes how the rest of the run plays. Decision: first pass is stat boosts only — active abilities come later (cheap to add on the new Spell system).
  • ✓ Shrine rooms hold a reward pedestal; bosses drop one where they die
  • ✓ Reward picker: room pauses, 1-of-3, first player to claim it takes it (shops stay unpaused — a shop decision is reversible, this one isn't)
  • ✓ First upgrade set: 8 stat boosts (+max HP, +speed, +damage, +armor, +lifesteal), flat and percent variants
  • ✓ Floor-gated upgrade pool (minFloor) + weapon-modifier magnitudes that scale with depth
  • ✓ Upgrades are per-player, held on the Player, cleared on run end
  • ✓ Per-instance weapons: each wielded weapon is its own object with its own modifiers; reward pedestals roll them
  • ✓ Attack pipeline: each stage (player → weapon instance → ammo → target) contributes to the Attack; Caster.scaleAttack is the single fold point
  • — Later: active abilities (dash, shield, projectile modifiers) as Spells
  • — Later: damage types + per-enemy vulnerabilities (slashing/fire/blunt) — the attack pipeline is built to accept this, but the taxonomy, per-enemy resistances, and weapon balance are their own pass
Art needed: First pass can use colored shapes + text labels. Proper upgrade icons are nice-to-have.
FLOOR 4 Room Variety Done ▶
Milestone: Two rooms in a row that feel completely different. Met — a floor now mixes combat, maze, shop, shrine, wave, timed and dark rooms, with traps as a cross-cutting hazard. Called done on rewards + traps; puzzle rooms deferred rather than rushed.
  • ✓ Treasure chests — interact for a guaranteed weapon, no choice, no cost, contents never previewed. Brown rolls 1 modifier, the 15%-rare gold rolls 2. (The standalone "chest room" type was retired: every non-reward room now drops a single reward pedestal on clear, and maze rooms additionally hide a chest at their deepest tile — so loot isn't gated to one rare room type.)
  • ✓ Trap tiles: 1% roll per eligible room (never boss/shop/shrine, never the start room); warps the whole party 1–3 floors forward. Rendered as a violet tile in plain sight, kept off doorways and room centers, so it's always avoidable
  • — Puzzle rooms: deferred out of Floor 4 — lever/switch objects trigger environmental changes (fire, wall tiles, doors). Needs a dedicated design pass before any code: what a switch targets, how state syncs, and whether a puzzle can ever softlock a room. Picked up in Floor 5, where the class movement abilities give them something to be built around and the "small, optional, multiple solutions" scope makes the softlock question moot
Already landed: the OO boss framework (aim-lock, movement behaviors) + three full movesets — Turtle Dragon (rock projectiles, Tremor Slam, Shell Spin), Wyvern (flying, diving swoop), Tengu Mask (three abilities). Shop & Healing Shrine rooms also exist. Chest art is imported (6-frame open animation, brown + gold). Art still needed: the trap tile is a flat violet placeholder, consistent with the other five flat-color tiles (only FLOOR has real art) — the whole tileset wants one art pass together.
FLOOR 4.5 Playtest Response Up Next ▶
Milestone: Two people can play a full run together without a bug ending the session. Everything here comes from the first external playtest — full notes and the decision log (D1–D18) in docs/playtest-2026-07-20.md. Only the room-entry grace window is still open as of 24 July — the stairs now read as stairs, done as part of the tileset overhaul in Floor 6.
1. Session-enders — these end a co-op run outright.
  • ✓ Barrier locks the second player out — if two players don't cross a doorway in the same tick, one is ejected back. Fix: one-way barriers — latecomers walk in, nobody walks out. Committed on entry, but the room starts without the whole party
  • ✓ P (add local player) spawns invisible, inside a wall — late-joiner spawn isn't validated against walkable tiles and the sprite never attaches
  • ✓ Menu rebuild — done. Escape opens a real pause menu (Resume / Inventory & stats / Options / Abandon run) that a run can be resumed from; it still peels overlays one at a time, and abandoning is a labelled entry behind a confirm rather than the default meaning of the key. ConfirmDialog.ts survives after all — a labelled entry and a confirmed one are not the same promise to the other three people in the party. Built together with the lobby below; see docs/lobby.md
2. Cheap feel wins
  • ✓ Interaction prompts ("press F") on chests, shop pedestals, offer pedestals, stairs — world-space prompts over every interactable, with the key resolved live from the rebind map rather than hardcoded
  • ✓ Slower enemies, more of them — enemy movement speed cut, and encounters now reveal as a batch on entry so a room reads as a group to position against
  • ✓ Enemy line-of-sight: no aggro through walls (also stops bosses chasing into the entry corridor)
  • ✓ Universal death feedback — several enemies currently just stop moving
  • ✓ Telegraph incoming spawns — every enemy reveal plays a dust puff (SpawnFX) at its position, and wave rooms were reworked from discrete waves into continuous attrition: each kill feeds in a replacement up to a concurrent cap, so there is no unannounced wave break to telegraph
  • ✓ Lock camera zoom at default — zoom is now a debug-only knob, out of player Options. The texture-variety pass it was papering over stays open in Floor 6
  • ✓ Make the stairs read as stairs — the tester didn't register there were multiple floors. Done in the tileset overhaul: the stairs are a drawn stairwell (a dark shaft with lit treads receding into it) instead of a flat yellow square, and the pulsing scale tween is gone — it was what made the tile read as a magic rune rather than architecture
  • ✓ Bug sweep done: projectiles pass through closed barriers · boss stun-lockable against a wall · walk-through chests · oversized crossbow icons · axes don't mirror when held · ghost "Wave 1/3" banner · knockback-immune enemies. Two did not reproduce and still need a live look: the oversized hammer icon (it renders at the same 16px as every sword) and the boulder hitboxes (cover blocks are one 32×32 collider under art that fills the whole cell — the snag is more likely the solver catching on seams between merged wall rects).
  • ✓ Move respawn behind the debug menu — the design is permadeath. respawnOnDeath is a debug flag now, and death became a real state rather than nothing: a player at 0 HP is downed — frozen, un-controllable, ghosted blue — and a standing teammate within REVIVE_RADIUS fills a revive bar to stand them up at half health. Descending carries a downed teammate down on their feet; the whole party down at once ends the run (one game_over broadcast, clients walk back to the menu)
  • ✓ Rebind weapon switch off Q/E
3. Co-op actually works
  • ✓ Per-player boss rewards — reworked into a shared 3-card offer with mutually-exclusive picks: the whole party sees the same three, each player spends one pick, and a taken card greys out for everyone. At most three items leave the pedestal
  • ✓ Party stairs prompt — the floor advances only once every living player is on the stairs (a downed teammate is carried down). Descending without clearing stays intentional
  • ✓ Enemy HP scales with party size — enemies and bosses both, fixed at run start. Scale the enemies, never nerf the player for bringing a friend
  • ✓ Minimap — Zelda-style dungeon minimap HUD; load-bearing once players split up to find the exit
4. Second bug pass — six more, 24 July.
  • ✓ Death did nothing — applyInput never checked isDead, so a 0-HP player kept walking and swinging, while the stairs gate counted only living players and stranded a solo player at 0 HP forever. Both holes closed by the downed/revive state above
  • ✓ Projectiles tunnelled through thin walls — wall checks are swept along prev→current in sub-tile steps instead of sampling only the new centre
  • ✓ One-way exit barriers popped open — commitment is now sticky per player, so standing in the doorway (where roomAt reads null) no longer un-commits you for a tick
  • ✓ Every run was the same dungeon — floor 1 now rolls a random seed. The Debug menu's seed still wins, and CreateRoomOptions gained an explicit seed for reproducible runs
  • ✓ Reward pedestals glowed forever in solo — a pedestal ghosts as soon as your pick is spent, not once all three cards are drafted, and the pulsing tween stops fighting setAlpha
  • ✓ Deferred spawning — an enemy you have never reached does not exist yet. The floor pass builds every enemy up front but holds it unspawned (out of synced state, no AI, not damageable) until a player enters its room. This replaced the old room-dormancy machinery outright
Design note: splitting the party to clear a floor faster was a play pattern we hadn't planned for and now want to support. It creates the tension the whole phase is built around — stick together for power, split up for speed. One-way barriers and the minimap are its prerequisites.
FLOOR 4.6 Playtest 3 Response Up Next ▶
Milestone: Co-op over the P2P transport is playable for the guest, and two people can play back-to-back runs without reloading. From the third playtest (2026-08-05, co-op, 2 players) — full notes in docs/playtest-2026-08-05.md. The signal this session was the guest experience: the host is authoritative and clean, the guest is where the seams are.
1. Critical bugs — these break a co-op session.
  • ✓ Enemies retain aggro after player death — a downed player still held enemy threat, so enemies kept attacking the corpse instead of pivoting to the survivor. Fixed: both target-selection paths (Enemy.pickTarget for regular/caster enemies, Enemy.closestPlayer for bosses) now skip downed players — aggro pivots to a living survivor the instant a teammate goes down, and an enemy whose only in-range target is downed drops to patrol. Regression tests in tests/engine/enemy.test.ts
  • ✓ Guest position rubber-banding — the guest snapped back mid-movement, frequently enough to make the game unplayable for the non-host. Root cause was two compounding flaws: the sim ran at 20 Hz while the client predicted at 60 fps (mismatched integrators drift in open space), and reconciliation was a binary snap-to-server that threw the player into their own past on every correction. Fixed with the standard authoritative-server prediction loop: (1) sim raised to 60 Hz so client and server integrate the same dt (network snapshot pump decoupled to 30 Hz so guest bandwidth doesn't triple; KNOCKBACK_DECAY retuned to keep the glide feel); (2) InputMessage gains a monotonic seq, the server drains a per-tick input queue and echoes PlayerState.lastProcessedInputSeq; (3) the client predicts on a fixed-timestep accumulator, keeps an unacked-input buffer, and reconciles by re-basing onto the server position and replaying the unacked remainder — so a correction reproduces the latency lead forward instead of snapping back, with the sprite easing toward the result and hard-snapping only on a real discontinuity (floor change / Blink). Movement math extracted to a Phaser-free movementPrediction.ts; unit + p2p seq/ack tests added. Verified in-browser (solo) that prediction converges to authority; the two-browser feel check (host + guest, real latency) is the one step the sandbox can't run and is left for a live session
  • ✓ Can't start a second run without a page reload — after a co-op run ended, the host couldn't create or join a new online room without Cmd+R. Read as a Party-teardown gap, but the cause was client-scene state: BrowseScene.joining is an instance field and Phaser reuses the scene instance across scene.start, so field initializers run once. A successful host/join set joining = true and hopped to the lobby; nothing reset it, so re-entering "Play Online" ran create() on the same instance with the flag stuck and silently swallowed every attempt. Fixed by resetting it at the top of create()
2. Design feedback — enrichment, not repair; the core loop held up.
  • ✓ Room enemy profiles ("mob voices") — fully-random mixed spawns read as chaotic. Define 2–3 curated enemy combos per room and roll randomly within a chosen profile — variety without all-random chaos. Done: engine/src/encounters/ (Skirmish/Swarm/Ambush/BrutePack), each a role-tagged list of enemy classes filled against a threat budget; SpawnDirector rolls a profile per room instead of exact-fill.
  • — Enemy stacking / no mutual collision — enemies can occupy the same tile and all attack at once, removing counterplay. Players want them to spread out or path around to surround, enabling bunch-for-cleave vs. spread-to-surround. Enemy–enemy collision is already on (ENEMY_BODY_PROFILE.solidMask includes Layer.ENEMY) — they still visually pile up because the collision body is a radius-5 foot circle under a big sprite, so what's actually left is a spread/surround steering layer on the flow field. Needs a design + perf pass — wider separation or steering multiplies solver cost
  • ✓ Dead-player spectate mode — a downed player waiting for a revive was left staring at their own corpse. Done: when the whole local party is downed, the camera follows a living remote teammate (sticky to one target until it falls) instead of the centroid; a mixed local party already ignores its downed members. Free-look was not needed — the fight is where the revive comes from.
FLOOR 5 Systems: Economy, Classes, Lobby Up Next ▶
Milestone: A run has an economy, classes have an identity, and strangers can find each other. Built in dependency order — currency, then lobby, then class powers, then puzzles.
Currency — replaces the HP-cost shop. Landed 23 July. Coins drop from enemies (art from the SOA2 Pickups sheet), lie 3s then home to a nearby player, and sweep into a shared purse shown on the HUD, which the shop spends. Economy constants + helpers live in shared/src/economy.ts, the Coin entity + drop/budget logic on the server, and there's a full economy.test.ts suite.
  • ✓ Enemies drop gold into one shared party purse. Shared deliberately: a contested resource makes players negotiate, and that's better co-op than four isolated wallets. (Rewards are personal, money is communal)
  • ✓ Shop tiers at 50g / 100g / 150g — the three pedestals sorted cheapest-quality-first so the tiers line up left→right
  • ✓ Budgeted, not per-enemy-priced. State the intent as constants — TARGET_SPEND_PER_PLAYER_PER_FLOOR = 100, TARGET_CLEAR_FRACTION = 0.7 — and derive the floor's gold budget (≈143g × players). SpawnDirector divides it across what it spawned, weighted by a goldWeight getter on each Enemy subclass. Enemy and room counts can then change freely without breaking the economy. No id→gold table
  • ½ Tier costs stay fixed and the per-floor budget stays flat across floors — both done. What still doesn't scale with depth is the shop's quality (weapons are still rolled uniformly regardless of floor) — the depth-scaled quality roll is the one open piece here
  • ✓ The shop is the only gold sink — shrines briefly charged 50g/pick and it played badly: being asked to pay for a reward you had already earned reads as a bug, not a trade-off. Shrine, boss, timed-clear and chest rewards are all free now, and the cost field is gone from the offer pedestal entirely rather than left pinned at zero. Still open: gold appearing as one of the choices on an offer pedestal
  • ✓ Rushing a floor short-changes you — uncollected coins are forfeit on descent, so that shortfall is the cost of speed, and it's what makes descending early an interesting choice rather than a free one
Classes get an identity
  • — Weapon categories restricted per class — Knight: hammers + maces (6) · Mage: staves (6) · Ranger: bows + crossbows (3) · Rogue: daggers + thrown (6). Swords, axes, spears and rapiers (31) stay open to everyone, so ~74% of the pool is shared and loot stays varied
  • — Restriction is one-way: weapons are restricted to classes, classes aren't restricted to weapons. A staff is Mage-only; the Mage may still swing a broadsword. Reversible if classes read too weakly
  • — Type-based, never string-based — each class declares its usable weapon categories as a compiler-checked getter on its Character subclass. Adding a category without assigning it is a build error, not a silent "nobody can use this"
  • — Loot rolls filtered by party composition — no staves drop without a Mage present. A filter on the roll, not a post-hoc reject, so the odds stay correct
  • — Movement ability per class, on its own cooldown: Blink (through bars/grates, over gaps) · Jump (over gaps) · Charge (through breakable walls) · Dash (distance). Never through locked barriers
  • — Class special power — Knight first: a regenerating shield, so the melee class can hold the front line without paying HP for it. Build it as the pattern; Rogue/Ranger/Mage powers get designed once we've seen it work
Menus & matchmaking — done, landed early alongside the Floor 4.5 menu rebuild. Full notes in docs/lobby.md.
  • ✓ Play Solo or Play Online at game start. Solo isn't a separate code path — it's a private room nobody can find, which is what keeps couch co-op working inside it
  • ✓ Browsable list of open rooms, join by 4-character code, or host your own — public-listed or private-by-code, chosen at creation
  • ✓ Lobby-only joins — a room's lobby and its run are the same Colyseus room in two phases, so "no dropping into a run in progress" is one room.lock() and there is no second door to keep consistent. Nothing simulates and nothing spawns until the host starts
  • ✓ A real lobby: roster with everyone's class and weapon, change your loadout in place, ready-up gating the host's Start, couch players added with P. Name and last loadout persist, so the two picker modals that used to stand between "Start" and the game are gone
  • — Still open: pause is room-wide (any player freezes everyone — fine on a couch, a griefing surface with strangers), and there is no reconnect — a drop loses the run
Puzzle rooms — unblocked, because the movement abilities are what they're built around.
  • — Scope that finally makes them safe: small, optional, multiple solutions. Because nothing behind a puzzle is required, no puzzle can strand a party — which was the exact softlock worry that deferred them out of Floor 4
  • — Obstacles that answer to a specific movement ability: a chest behind bars (Blink), across a gap (Jump/Blink), behind a crumbly wall (Charge)
  • — Pressure plates — a second player stands on it, or shove a boulder onto it. Torches to light (or extinguish) to reveal a chest. A pot on a plate whose removal springs a trap or a secret
  • — Material solutions: burn wooden barriers with magic, shatter stone with a hammer, blow up crumbly walls
  • — Four-Swords-style co-op: boulders that need two players, plates that need multiple bodies
Open, tracked in docs/playtest-2026-07-20.md §7: what each class starts with · whether rolls should favor the party's exclusive categories rather than merely permit them · whether ClassPower is a new OO family or the Knight's shield is just an always-on Upgrade the class is born with · how much of the lobby is real matchmaking vs. UI over Colyseus room listing.

ONGOING Engineering & Tooling Done ▶
Not a floor — the substrate work that runs alongside the content phases. Kept here so it stops looking like nothing happened on the weeks it was the whole job.
  • ✓ Vitest suite at the repo root (22 July) — ~735 tests, 96% lines, covering shared/ and server/ with the real physics, entities, combat, directors and GameRoom itself, no server and no browser. It replaced the old verify-*.ts golden-output harnesses, which pinned HP and damage totals and so failed on every balance pass without ever catching a real defect. The rule now: assert behaviour and relationships, never balance numbers
  • ✓ Weapons refactored to be object-oriented — a three-level chain (Weapon → category base → the weapon), stats as compiler-checked getters, WEAPON_REGISTRY derived from the class array rather than hand-maintained
  • ✓ Ammo refactored the same way — one class per projectile under a category base (arrows / bolts / boomerangs), AMMO_REGISTRY derived
  • ✓ Typed state views (shared/src/stateViews.ts) — every server schema implements its synced shape, so renaming a @type field is a server-side compile error instead of a silent undefined on the client twenty files away
  • ✓ Hitboxes measured from art, never declared — melee hurtboxes generated from the FX strips, enemy hurt bounds generated from the spritesheets. There is no per-weapon reach number and no hand-tuned enemy hurt size left to drift
  • ✓ Dev balance tools — enemy stat spreadsheet with source write-back, plus a weapon + ammo balance tool
  • ✓ Untrusted client ids validated — characterClass/characterType go through resolvers rather than being cast; an unknown class used to crash onJoin
  • ✓ Containerized deploy — Docker + Caddy, esbuild-bundled server, one origin serving the client and Colyseus over same-origin /ws; CORS added so join-by-code works in dev too
  • ✓ Rebindable keys in Options, and the six older DOM overlays folded onto one shared menuDom stylesheet
Standing rule: content families are OO with the class list as the source of truth — enemies, bosses, weapons, ammo, upgrades, and room challenges. Registries exist only where something is genuinely referenced by id across the wire, and are derived, never authored.

Open Questions
Resolved — July 2026
Stat boosts only for the first upgrade set, or active abilities too?
Decided: stat boosts first. +max HP / +speed / +damage / +lifesteal, per-player, floor-scaled — fast to build and balance, gets the run-defining loop working end-to-end. Active abilities (dash, shield, projectile modifiers) come as a later pass, and are cheap to add now that everything casts through the unified Spell system.
Resolved — July 2026
In co-op, who picks a reward — each player, or the first to reach it?
Decided: first player to claim it. One pedestal, one winner. Much simpler than per-player choice lists, and it creates a real conversation between teammates about who needs the pick. Revisit if it turns out to feel mean rather than tense.
Open — direction noted
How far does weapon modification go?
Scope north-star: Souls-like breadth. Many weapon types sharing artwork, each dealing different damage types, each individually modifiable — rolled stats on spawn, upgrades applied to a specific weapon, not just to the player. This is the target the per-instance weapon work and the attack pipeline are built toward; it is deliberately not all being built at once. Damage types are the first deferred slice.

What is the weapon inventory cap?
Leaning 1 or 2. The tester finished a run holding 20 weapons — weapons are noise. I want a hard, choiceful 1; he wants a ranged+melee pair (2). Ties into weapon scarcity: target ~1–2 weapon-swap options per floor, possibly per party not per player. Shop-rarity + no-weapons-from-room-clears already landed (65e40c6); re-test density before deciding.
Open — 27 July playtest
Total floor count and floor size?
Currently 10 (arbitrary; not enough bosses). Considering 3–4 large floors, which the existing bosses can cover. Tester's target per-floor time: full exploration ≤ 8–10 min. Floors should get bigger. Wants to time a full clear vs. a speed run to calibrate.
Open — 27 July playtest
Healing model — full heal every floor?
Floors currently restore full HP on descent. Both of us think some healing is good but full-every-floor is too much. Lean: add other heal sources (a one-time heal station in each shop), then remove the automatic full heal.
Open — 27 July playtest
Ranged vs. melee balance.
Range feels inherently stronger — bow/mage reach deep runs, melee dies in the first rooms; spears/trident have great range and power. Root cause: enemy damage is all touch-based (no telegraphed swings), so ranged just kites. Real fix is enemy attack swings (big). Interim levers: ranged deals less damage, weapon-specific range (bow > blowgun > thrown star) so nothing hits off-screen, spear combos that start short and lengthen. Slow weapons feel bad and need faster swings or to be really worth it.
Open — 27 July playtest
Buff strength — shrink magnitudes or reduce frequency?
Stacked +40% / +40% / +20% attack in three rooms. We both want a buff every room, so favor smaller numbers over rarer buffs. Berserk's −15% HP is the only current brake; vitality buffs felt fairly costed.
Open — 27 July playtest
Armor / trinket slots as a gold sink + weapon-flood diluter?
Simple equipment slots — Armor / Helmet / Necklace / Ring — purely mechanical (no art needed; stats worn invisibly). Gives gold something to buy besides weapons (he ended with 300–400 unspent) and dilutes weapon-heavy loot with other rewards. Tester is drafting an effect list. Sub-question: which effects are player-permanent vs. weapon-bound vs. timed (emerging model: potions → player; a vial of poison → the held weapon, non-transferable, maybe timed unless your class has it natively).

Should the Mage cast discrete spells instead of a staff bolt?
Leaning yes. Pick up spells like weapons, swap with Q/E, favor AOE over single-target. Keybinding is easy on keyboard (1–9), unclear on controller — that's the blocker. Related flavor call: he wants mage bolts to pierce and stars not to; my intuition is the reverse (bolt stops, spinning star ricochets; boomerang already passes through).

Trap tile reads as a shortcut, not a hazard.
The floor-skip trap ("magic circle") looks like an alternate exit and rewards stepping on it (full heal + skip ahead), so the tester was pleased to hit it — backwards from intent. Needs to read as dangerous/ambiguous.
